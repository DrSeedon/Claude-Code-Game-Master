# R5 requirements and alternatives matrix

Status: Phase 1 research decision input. “Selected” means the safest implementable MVP contract from current primary-source and synthetic evidence; it does not claim measured room latency, recognition quality, browser compatibility, or provider availability.

## Requirements matrix

| Requirement | Unsafe baseline | Browser-direct Deepgram | VPS speech proxy | MVP contract | Falsifier / deterministic oracle |
|---|---|---|---|---|---|
| AI listens only when addressed | Continuous cloud stream/VAD decides what counts | Browser can gate audio, but a UI bug can still transmit ambient frames | VPS accepts frames only for a server-admitted capture | Mandatory per-character press-and-hold `Мастер`; no audio socket/frame before accepted activation | Ambient synthetic frames produce zero provider frames and zero drafts; network capture outside PTT contains zero audio bytes |
| Character binding without diarization | Infer speaker identity from a shared microphone | Browser attaches selected actor | Server validates selected actor against the R7 session allowlist before minting `capture_id` | Actor is bound at `input.capture.start`; audio frames contain only the server-issued capture identity | Actor cannot change after the first frame; another-room/disallowed actor produces zero capture/provider/world rows |
| Capture format | Browser-dependent `MediaRecorder` blob type and irregular `timeslice` | Can stream raw PCM directly | Can normalize and validate before provider forwarding | `AudioWorklet` → mono `linear16`, 16 kHz, little-endian, 20 ms/640-byte normal frames; requested echo cancellation/noise suppression/AGC are diagnostics, not assumed facts | Wrong capture/generation, gap, empty/odd/wrong-size payload, or unsupported actual track settings fails the capture and creates no draft |
| Credential custody | Long-lived provider key in browser | Temporary JWT in `Sec-WebSocket-Protocol`; default 30 s; token grants `usage::write` to several core voice endpoints | Browser has no provider credential; VPS uses server-only key | Select proxy for MVP | Browser bundle/storage/URL/headers/logs contain no long-lived key or Deepgram JWT; failure is release-blocking |
| Provider connection lifetime | One indefinite stream with ambiguous turn ownership | Direct per-capture or warm connection | Proxy can own one connection per capture | One provider WebSocket per accepted PTT capture; open concurrently with the room-audio socket; `CloseStream` after ordered `input.audio.end` | Any provider event cannot be assigned to exactly one capture/request/generation → fail attempt, no draft |
| Interim/final handling | First plausible transcript becomes a command | Browser assembles mutable events and submits text | VPS assembles provider events centrally | Interim is ephemeral UI only. Deduplicate and concatenate all `is_final:true` segments. PTT release—not a pause—defines the utterance. `Metadata` plus subsequent normal close after `CloseStream` closes the set | Interim rewrite, multiple finals, multiple `speech_final`, duplicate final, late final, and Metadata-then-abnormal-close fixtures yield at most one immutable transcript; conflicting duplicate fails |
| Approval and correction | Final transcript executes immediately | Browser submits transcript; server must still review | Proxy submits an internal finalized event to R4 | `speech.finalized` causes idempotent R4 `receive`; R4 creates the card. Correction creates immutable draft v+1 and rotates approval nonce; only exact current approval can execute | Interim/final alone changes zero world rows; stale version rejects; duplicate approval returns stored result; correction does not mutate world |
| Physical declared roll | Any number in speech becomes a result | Client-side parser is spoofable but result is still untrusted input | Server can bind parser to current core state | At capture start the server freezes the actor's current `pending_roll_id` and aggregate revision; transcript needs an explicit marker plus one deterministic total; closed `roll.declared_correct` creates v+1; current approval rechecks both identity and revision | “У меня 17 стрел” creates no roll candidate; “Бросок — 17” does; structured correction to 18 yields v2; approve v1 or after revision change rejects; duplicate current approval records one declaration |
| Barge-in / interruption | Microphone hears buffered AI speech; game turn replays | Browser can stop local playback but cannot fence another audio leader itself | Server can fence the current R7 audio lease/context | Pointer/key down stops local buffer first; accepted capture makes the server select and cancel the current `line_id/context_id` and increment the audio fence. It never re-enters the kernel | Late audio chunks for the old fence are discarded; world/aggregate versions and mutation count do not change |
| Reconnect | Auto-submit last interim or blindly resend audio | New token and provider session required; browser buffer/replay needed | New room-audio/provider sessions required; server can centralize failure state | Any control/audio/provider disconnect before durable final candidate marks the attempt failed, clears partials, and offers Retry/Type. Reconnect rehydrates R7 only; it never auto-resends audio/approval | Inject disconnect after each stage; no partial draft, no duplicate, late old-generation events ignored; a new PTT capture is a new ID |
| VPS restart | Recover provider stream from guesses | Browser may still have provider state the VPS cannot attest | Active proxy stream is lost | Persist attempt metadata plus the complete immutable `speech.finalized` referenced by `candidate_event_id` in the same ready transaction. `armed/capturing/finalizing` on restart → `failed`; `ready` replays only the same R4 receive; `submitted` reads stored R4 result | Crash before candidate → no draft. Crash after atomic candidate/reference persist → one draft. Restart never asks provider to reconstruct an unknown stream |
| App privacy and retention | Store recordings and transcripts in debug logs | Raw audio avoids VPS but still goes to provider; token exists in browser | Raw audio transits VPS memory and provider; no browser provider token | Raw audio and interim text are memory-only and dropped on terminal/failure; no recording/file/log/backup. Final transcript/draft follows campaign-turn retention; operational logs contain IDs, timing spans, sizes and enum errors only | Synthetic raw-audio canary absent from durable records, results and audit; repository scan finds no audio; logs contain no transcript/token |
| Provider privacy | Assume “streaming” means zero retention | Same provider contract | Same provider contract | Send `mip_opt_out=true`; choose the applicable regional endpoint; real room audio remains blocked until account/DPA retention and deletion terms are recorded. Deepgram request logs and customer-data terms are not treated as zero retention | Missing account/DPA/region/retention snapshot or opt-out evidence → no real participant audio |
| Failure fallback | Repeated reconnect until it works | Typed fallback possible | Typed fallback possible | Retry microphone by explicit user action or use the existing authenticated final-text/draft path. Provider outage never blocks typed play and never silently changes route mid-capture | Provider unavailable trace shows an error card and enabled typed input; zero draft until the user explicitly supplies text |
| Latency | Promise a number from provider marketing | One audio network leg; provider handshake/token issuance may add setup | Two audio network legs; centralized normalization; provider handshake may overlap speech | No numeric SLA exists. Instrument the budget in `speech-input-protocol.md`; retain proxy unless a predeclared room gate is later missed and direct passes all security/correctness gates | Every span is emitted with monotonic timestamps; route comparison uses paired p50/p95 distributions and a threshold frozen before data collection |
| Wake word | Continuous cloud transcription of room talk | Possible but still needs actor binding and false-activation testing | Cloud wake word adds continuous transfer through VPS/provider | Not in MVP. A later local-only detector may emit the same untrusted activation intent only when a server-known actor is selected; PTT remains mandatory fallback | Any ambient cloud transfer, inability to bind actor, missed/false activations over the predeclared room corpus, or demo complexity → omit |

## Transport alternatives

| Alternative | Correctness boundary | Security/privacy | Latency evidence | Operational cost | Decision |
|---|---|---|---|---|---|
| **A. Browser → Deepgram using temporary token** | Browser assembles finals; VPS treats submitted text as untrusted draft input; approval still protects world | No long-lived key, but the browser receives a temporary `usage::write` token carried in a WebSocket subprotocol header; access/error-log redaction must be proven | Official docs describe direct access as useful for latency-sensitive clients; no target-room measurement exists | Token mint/refresh, browser provider SDK/reconnect, two independent socket lifecycles | **Reserve as measured optimization.** Reopen only if proxy misses a frozen latency gate and A passes token/log/reconnect/cross-browser tests |
| **B. Browser → VPS → one Deepgram stream per PTT capture** | VPS owns capture ID, provider request, final assembler and idempotent R4 handoff; per-capture socket is the finality fence | No provider credential in browser; raw audio briefly exists in VPS memory and still goes to Deepgram | Extra relay leg is real; magnitude is unmeasured. Provider and audio-socket handshakes can overlap speech | Two WebSockets per capture, server bandwidth/backpressure, simpler browser/provider trust boundary | **Selected MVP route.** It closes credential, provenance, finality and recovery invariants without a latency claim |
| **C. Browser → VPS → warm long-lived Deepgram stream** | Must serialize captures and prove a terminal barrier before the next capture | Same credential boundary as B; idle connection sends no audio but needs keepalive | Avoids per-capture provider handshake; unmeasured | Keepalive, timeout/reconnect, accumulated timestamp and late-final ownership complexity | **Rejected for MVP reliability.** `Finalize` completion marker is not guaranteed when little audio is buffered; reconsider only with a measured barrier protocol |
| **D. Record then prerecorded STT** | File boundary is simple | Creates retained raw recording unless carefully deleted | Cannot stream interim; end-to-draft necessarily waits for upload/processing; unmeasured | File lifecycle, deletion, larger retry payload | **Rejected.** Conflicts with no-recording/data-minimization goal and interactive feedback |

## Decision basis

The proxy is selected because the current evidence can close security, event ownership, finality, and recovery invariants deterministically. It is **not** selected because it is proven faster or more accurate. Browser-direct remains a legitimate optimization: Deepgram officially supports temporary browser tokens and client-side WebSocket authentication, but its broader temporary credential surface and browser-owned reconnect must be justified by measured benefit.

Primary-source evidence and confidence labels are in `research.md`; exact messages, state transitions, binary framing, failure behavior, retention and timing spans are in `speech-input-protocol.md` and `protocol-schemas.json`.
