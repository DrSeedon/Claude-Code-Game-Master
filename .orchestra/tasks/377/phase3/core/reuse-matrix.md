## Third-party closure checklist

Before any literal copy into the later private product, its transfer manifest must record:

1. exact source commit, file and line/function range;
2. Git authors plus evidence of assignment/permission for every non-owner contributor (Git blame is attribution evidence, not ownership proof);
3. source and destination license notices, including any share-alike/network-copyleft condition that applies to the selected expression and linkage/deployment;
4. direct/transitive dependency names, versions, licenses and notices—never import a source manifest/lock wholesale merely to make copied code run;
5. absence of campaign state, speech, prompts, provider profiles/keys, logs, cookies, databases, production/deploy configuration and unlicensed fixtures;
6. SRD 5.2.1 official attribution and a separate trademark/branding decision;
7. asset, generated-image, music/SFX, voice/voice-clone and recording consent/provenance, all outside the first-party code grant;
8. a destination test that proves the extracted behavior through the Unified Core boundary rather than preserving obsolete WorldGraph/Orchestra topology.

The default for mixed or high-coupling rows is behavioral reimplementation. Authorization makes literal reuse possible after closure; it does not make literal reuse cheaper or architecturally correct.
